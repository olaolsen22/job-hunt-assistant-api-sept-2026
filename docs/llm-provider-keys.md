# Personal AI provider keys

## Storage and deployment

Personal keys are encrypted with ASP.NET Core Data Protection. Protection is bound to the user, provider, and immutable credential ID. Replacing or removing a credential erases its stored ciphertext and retains metadata for usage history. These operations do not revoke the key at the provider or erase prior backups; revoke compromised keys at the provider too.

`DataProtection:KeyRingPath` controls persistence. In Docker, compose sets `DataProtection__KeyRingPath=/data/dp-keys` inside the existing `jobhunt-data` volume. Container recreation must preserve that volume. Locally the default is `<API content root>/.local/dp-keys`, ignored by Git. Set the environment variable to an existing persistent private directory to use another location. The application uses the stable Data Protection application name `JobHunt.Api`.

New key-ring directories are created with owner-only access on Unix. Existing directories must also be accessible only to the runtime account; check their permissions when deploying. Filesystem persistence does not encrypt the key ring itself. Possession of both the database and an unwrapped key ring permits decryption. Certificate wrapping can be added in deployment when required.

Back up and restore the database and its matching key ring together as sensitive material. `make backup` backs up database/WAL/SHM files; it does not back up the key ring. The generated BYOK migration preserves existing Gemini usage as shared history. Review migrations before applying; a normal migration is applied at the next API startup. Restoring older database backups loses later configured credentials, which must be re-entered.

A saved key whose protection material is missing returns `credential-unavailable`; it never causes an automatic shared-key call. Changing the Data Protection application name at the first rollout can invalidate existing auth cookies, requiring sign-in again. Keep the name and key ring stable afterward.

## Key management

Only Owners can manage personal keys; Guests continue to use shared Gemini. One active key is allowed per user/provider: `gemini`, `anthropic`, `openai`, or `mistral` (exact lowercase names). API keys are write-only. Status responses contain safe IDs, last four characters, configuration state, and timestamps.

```graphql
query {
  providerKeys(includeRetired: false) {
    provider configured credentialId last4 createdAt retiredAt
  }
}

mutation SetKey($provider: String!, $key: String!) {
  setProviderKey(input: {provider: $provider, apiKey: $key}) {
    providerKey { provider configured credentialId last4 }
    errors { ... on ProviderKeyError { message code } }
  }
}

mutation RemoveKey($provider: String!) {
  removeProviderKey(input: {provider: $provider}) {
    providerKey { provider configured }
    errors { ... on ProviderKeyError { message code } }
  }
}
```

Pass the secret as a GraphQL variable over HTTPS. Do not persist it in UI storage or log mutation variables. Blank keys, unsupported providers, control characters, and secrets over 4,096 characters are rejected locally. Key validation makes one authenticated model-list request with a 10-second timeout. A successful metadata request does not guarantee model access, inference credit, or quota. Failed validation never replaces the current key. Removal is idempotent. `includeRetired: true` includes metadata for labeling previous credentials' usage; retired secrets are erased.

Stable errors are `invalid-input`, `forbidden`, `invalid-key`, `rate-limited`, `timeout`, `provider-error`, `credential-unavailable`, and `conflict`. Raw provider messages are never returned. Inference has a two-minute timeout and no automatic SDK retries or credential failover. The UI should prompt the user to update/remove the key or choose another available model.

## Model choices and routing

```graphql
query {
  llmModels {
    defaultModel
    models { id label provider modelId keySource credentialId }
  }
}

mutation DefaultModel($model: String) {
  setDefaultLlmModel(input: {model: $model}) {
    llmModels { defaultModel }
    errors { ... on Error { message } }
  }
}
```

Use `models.id` as the existing optional `model` input on all AI mutations and default selection. `modelId` is the native provider ID, used in parse-job and usage records. Gemini IDs remain unchanged. Other selection IDs are qualified, for example `openai:gpt-4.1-mini` and `anthropic:claude-haiku-4-5-20251001`.

`Llm:Gemini` still configures the shared key, default, allowlist, and shared limits. `Llm:Providers:Anthropic`, `Llm:Providers:OpenAI`, and `Llm:Providers:Mistral` configure personal-provider model arrays with `Id`, `Label`, `MaxOutputTokens`, and `ContextWindowTokens`. Catalog entries must have unique selection IDs, at least 32,768 supported output tokens, and a context window of at least 150,000 tokens. Values are operator-declared capabilities, not remotely inferred account permissions. No provider URLs are accepted from the client.

The initial text catalogs use [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini), [Claude Haiku 4.5](https://platform.claude.com/docs/en/models/haiku-4-5/overview), and [Mistral Large 3](https://docs.mistral.ai/models/mistral-large-3-25-12). Review catalog entries when providers retire models. Model availability and limits can still depend on the user's provider account.

Owners see configured Gemini models and other provider models only while they have that provider's active key. Other users see only shared Gemini's default. Gemini uses the Owner's personal Gemini key when present, otherwise shared Gemini; an Anthropic key does not change that Gemini route. Personal-key failure returns an error without switching to any other key or provider. To switch explicitly, choose another available model, or remove the failing Gemini key to use the shared Gemini key. A stored default whose catalog entry/key disappeared resolves to configured Gemini; an explicitly requested unavailable model is rejected before URL fetches or AI calls.

## Usage per credential

Personal-provider calls can also have an Owner-selected daily request limit through `setLlmCallLimit` and `llmCallLimits`. Limits start disabled, span all models and replaced credentials of that provider, and count admitted attempts before dispatch. Shared Gemini is exempt. All AI mutations accept optional `requestId` for durable duplicate protection; one operation per user can run at a time. See [AI call safeguards](llm-call-safeguards.md) for payloads, safe errors, uncertain-attempt accounting, and batch stopping. Existing provider quota estimates remain separate from these application limits.

The same routing applies to `parseListing` (FULL/QUICK/COMPANIES), `parseUrl`, `parseListingFromUrl`, `parseProfileCv`, `analyzeTailoredCvSection`, and `analyzeAllTailoredCv`. Listing operations return their existing SUCCEEDED/FAILED parse jobs; CV parsing returns its existing candidate/failed result, and tailored analysis returns succeeded/failed section results. Invalid output still fails decoding. Parse jobs record actual provider/native model. Only an attempted inference creates a usage row. Credential errors do not implicitly save profile content or tailored drafts.

```graphql
query Today {
  llmUsageToday {
    provider model keySource credentialId
    requests inputTokens outputTokens requestsLimit remainingRequests resetsAt
  }
}

query History($credential: String) {
  usageDaily(days: 30, credentialId: $credential) {
    day provider model keySource credentialId
    requests inputTokens outputTokens estimatedCost
  }
}
```

Today follows the effective default model and credential. Shared Gemini requests/tokens sum all users' shared-key calls. Personal totals include only this user's resolved credential and model. Other users' personal activity is never included. Failed inference attempts count as requests; missing tokens add zero. Keys that cannot be decrypted cause no inference attempt and no inference usage row.

Caller cancellation still aborts the operation. An attempt already started retains unsuccessful usage with code `canceled`; pending caller-owned content is not saved by that audit write. Cancellation before an attempt creates no usage row.

Daily history defaults to shared aggregates plus this user's personal credentials, including retired ones. `credentialId: "shared-gemini"` selects shared history; a current or retired personal credential ID selects its own history. Foreign or unknown IDs return the same safe unavailable error. Group history by day/credential/provider/model rather than model alone: key replacement creates a new credential ID and preserves the old group. Existing rows migrate as shared history.

Daily buckets use Pacific midnight for compatibility. This is a reporting day, not a claim about a personal provider's billing reset. Only shared Gemini uses configured per-model RPD limits; personal `requestsLimit` and `remainingRequests` are null. Counts describe this application's calls and exclude other applications using the same key. They do not enforce or establish provider-wide remaining quota.

Optional estimates use `Llm:ProviderPricing:{provider}:{native-model}:InputPerMTok` and `OutputPerMTok`. Legacy `Llm:Pricing:{native-model}` remains a Gemini-only fallback. Missing prices return null, never zero. Estimates omit provider billing details such as cache rates/discounts and are not invoices. `usageDaily.days` remains 1–90 (default 30), with no row for empty groups.
